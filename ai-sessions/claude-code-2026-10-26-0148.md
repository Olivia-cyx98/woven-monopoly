They don't use it yet. `TestBoard` exists and is wired up, but nothing calls it.

**How it's wired up:**
- [spec_helper.rb:4](spec/spec_helper.rb#L4) loads every file under `spec/support/`.
- [spec_helper.rb:7](spec/spec_helper.rb#L7) has `config.include TestBoard`, so `test_spaces` and `test_board` can be called from every example group.

**What each spec does instead:**

| Spec | How it gets a board |
|---|---|
| [game_spec.rb:4-13](spec/woven_monopoly/game_spec.rb#L4-L13) | Builds its own copy of the same four spaces in `let(:board)` |
| [board_spec.rb:6-13](spec/woven_monopoly/board_spec.rb#L6-L13) | Builds its own copy in `let(:spaces)` |
| [rules_spec.rb:6-15](spec/woven_monopoly/rules_spec.rb#L6-L15) | Builds its own copy in `let(:board)` |
| [player_spec.rb](spec/woven_monopoly/player_spec.rb) | Doesn't need a board; it only creates a `Player` |
| [result_spec.rb:6](spec/woven_monopoly/result_spec.rb#L6) | Uses a different two-space board, so the helper doesn't fit |

A search for `test_board` and `test_spaces` only finds the definitions in [test_board.rb](spec/support/test_board.rb).

**To switch them over**, you'd replace the duplicated blocks:

```ruby
# game_spec.rb and rules_spec.rb
let(:board) { test_board }

# board_spec.rb
let(:spaces) { test_spaces }
```

Keep the `let` wrapper. `test_board` builds a new `Board` every time it's called, but `let` keeps one per example. Without it, `space(name)` in `rules_spec` could look up a space on a different board from the one `Rules` was given, and ownership checks would fail.
